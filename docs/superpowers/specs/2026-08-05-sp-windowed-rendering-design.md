# SP 点数分配窗口化渲染设计

## 目标

解决 SP 点数分配面板在预计兑换套数异常增大时一次性生成数万张卡片、导致页面打开卡顿甚至冻结的问题，同时保留当前页面的两行视口、四行缓冲、整行滚动和一键分配后的自动定位。

## 已确认的行为

- 不设置 300 套之类的业务硬截断，不改变收益计算结果。
- SP 面板的可视窗口仍保持两行高度，DOM 额外保留前后一行缓冲，因此通常渲染四行卡片。
- 使用显式网格行轨道维持完整滚动长度，用户仍可以访问全部轮次。
- 滚动吸附到整行，视口显示完整的两行，前后缓冲行避免切换时出现空白。
- 点击“一键最优分配”后，仍按全局收益最高的轮次分配 SP。
- 分配完成后，自动滚动到 SP 点数最多的那一行；同点数时选择更靠前、收益更高的行。
- 手动增减 SP 时保持当前滚动位置，不强制跳转。
- 清空分配时清空高亮，但不改变当前滚动位置。

## 方案

### 1. 窗口化渲染

现有 `renderSPPanel` 不再遍历 `1..totalSets` 并为每一轮创建 DOM。它改为根据容器宽度计算列数，再将轮次按网格行分组：

1. 计算总行数 `ceil(totalSets / columns)`。
2. 根据 `scrollTop` 和固定行高确定当前可视起始行。
3. 创建当前可视的两行，以及前后一行缓冲，通常共四行卡片。
4. 使用显式网格行轨道，使滚动条仍代表完整的轮次范围。
5. 监听滚动事件，并通过 `requestAnimationFrame` 合并连续滚动事件；当起始行变化时重新渲染窗口。

网格继续使用现有的两行可视高度、`scroll-snap-type` 和平滑滚动样式。窗口外的轮次只保留数字范围和高度信息，不创建按钮、文本节点或卡片 DOM。

### 2. 一键分配后的定位

`autoAllocateSP` 在生成最优分配 Map 后，统计每个网格行的 SP 点数总和。选择点数最多的行；出现并列时选择轮次编号更小的行。调用统一的定位函数，将滚动位置设置为该行的顶部，并以平滑方式滚动。自动滚动期间暂时忽略中间位置的滚动事件，避免监听器把动画起点误判成新的窗口；到达目标行后恢复正常窗口更新。目标行前后一行缓冲会同时保留，避免动画过程中出现空白。

自动定位只影响展示，不改变分配算法、SP 上限或收益计算。

### 3. 异常数据保护

- `totalSets` 不是有限非负整数时，清空 SP 网格并显示“预测套数异常，暂无法显示 SP 分配”的提示。
- `totalSets` 为 0 时显示空状态，不创建占位卡片。
- 所有窗口起止行都经过整数化和边界限制，避免滚动值导致负索引或越界。
- 不对正常业务套数做 300 套截断；保护目标是 DOM 数量，而不是修改模拟结果。

## 数据流

```text
calculate()
  ├─ 计算 latestProjection.totalSets
  ├─ 保留现有 SP 分配与收益计算
  └─ renderSPPanel()
       ├─ 读取总轮数、列数、当前 scrollTop
       ├─ 计算可视行窗口和前后缓冲
       └─ 只渲染窗口卡片

autoAllocateSP()
  ├─ 使用现有全局最优分配算法
  ├─ calculate() 更新分配状态与窗口
  └─ focusSPAllocationRow() 定位到点数最多的行
```

## 影响范围

- 修改 `site/index.html`：SP 窗口状态、窗口渲染、滚动监听、异常状态和自动定位。
- 修改 `site/calculator-ui.css`：占位行和空状态样式；保留现有两行高度与滚动吸附规则。
- 不修改 `stardust-rules.js`、奖励公式、抽卡概率、合成规则和现金流计算。

## 验证标准

1. 普通 80 套数据打开后，SP 面板只存在当前两行及前后一行缓冲对应的卡片 DOM。
2. 滚动时始终吸附到整行，不能停在半行位置。
3. 将测试数据临时扩大到数万轮时，页面仍能打开，DOM 数量不随总轮数线性增长，且窗口切换过程中不出现空白。
4. 点击“一键最优分配”后，视图自动跳到 SP 点数最多的行，并能看到该行高亮卡片。
5. 手动增减、清空分配、修改 SP 上限后，现有计算结果和输入缓存行为不变。
6. `npm run build` 成功，部署产物包含更新后的 HTML 和 CSS。
